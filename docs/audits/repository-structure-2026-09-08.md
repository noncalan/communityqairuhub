# Repository structure audit — 2026-09-08

## Outcome

The repository now separates executable application code, database infrastructure, documentation, public assets, scripts, and archived material. No file was deleted during the cleanup.

## Moves and renames

| Before | After | Reason |
| --- | --- | --- |
| `app/` | `src/app/` | keep all executable Next.js code under `src/` |
| `components/` | `src/components/` | identify frontend code clearly |
| `lib/` | `src/lib/` | colocate application services and data access |
| `types/` | `src/types/` | colocate application types |
| `proxy.ts` | `src/proxy.ts` | required location when App Router uses `src/` |
| `docs/community-current-state.md` | `docs/product/mvp-status.md` | explicit product scope and status |
| `docs/core-api.md` | `docs/reference/core-api.md` | API reference rather than general notes |
| `docs/navigation-performance.md` | `docs/architecture/navigation-performance.md` | current architecture documentation |
| `docs/performance-pass-1.md` | `docs/audits/navigation-performance-2026-09-07.md` | dated point-in-time report |
| `docs/phase-4-preview-tester-checklist.md` | `docs/operations/preview-testing.md` | active operational checklist |
| `docs/security-audit-phase-3.md` | `docs/audits/security-2026-08-14.md` | dated point-in-time report |

| five unused Next.js starter SVGs | `archive/nextjs-starter-assets/` | preserve instead of deleting unused assets |

Ignored local files were also moved without deleting them:

- `.qairu-local.*.log` → `.local/logs/development.*.log`;
- `tsconfig.tsbuildinfo` → `.cache/typescript/tsconfig.tsbuildinfo`.
- the pre-move `.next/` cache → `.local/cache/next-before-src-move-20260908/`; a clean `.next/` was generated by the successful production build.

Eight empty, untracked directories with no files were removed: `hooks`, `(marketing)`, `phase2cqa`, `qa-preview`, `__phase2c_qa`, `lib/actions`, `lib/queries`, and `supabase/snippets` in their former locations.

## Duplicate review

No byte-for-byte duplicate exists among tracked files.

Similar files that are intentional:

- `/login` and `/sign-in` both render the same sign-in form. Both routes are referenced, so they were preserved as compatibility entry points; canonicalising one into a redirect is a later product decision.
- `Brand` and `ClientBrand` share markup, but use different navigation behavior and are both active.
- `components/demo/*` and live components are parallel implementations for the two documented application modes, not obsolete copies.
- repeated Next.js names such as `page.tsx`, `layout.tsx`, `route.ts`, `loading.tsx`, and `not-found.tsx` are framework conventions.

## Suspicious or historical material

- `community-product-spec.md`, cited by the MVP audit, is not present in the repository. Restore it or link the authoritative external specification.
- `.env.example` uses `localhost:3010`, while `supabase/config.toml` uses `127.0.0.1:3000` for Auth redirects. The mismatch is documented and must be resolved before Auth testing.
- `docs/audits/` contains historical snapshots. They remain useful evidence but should not override newer code or current product documentation.
- `docs/prototypes/university-clubs-telegram.md` and the matching code/migration are explicitly prototype scope.
- `public/og.png` is large (about 1.1 MB) but actively referenced by application metadata, so it was retained.
- `CLAUDE.md` contains only `@AGENTS.md`; this is a small tool compatibility pointer, not an abandoned document.
- Node's direct TypeScript test runs emit `MODULE_TYPELESS_PACKAGE_JSON` warnings because `package.json` has no explicit module type. Tests pass; adding `"type": "module"` should be evaluated separately because it can change Node module semantics.

## Candidates for deletion after owner confirmation

- `archive/nextjs-starter-assets/`: five unused default SVGs with no repository references;

- local generated directories such as `.next/`, `.cache/`, `.vercel/`, and `node_modules/` whenever local disk cleanup is wanted; they are reproducible and not tracked.

Do not delete the dated audit documents until their evidence value and retention requirements have been reviewed.
